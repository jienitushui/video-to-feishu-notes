# 笔记内容与 note.json

先阅读素材 manifest、完整转写稿和所选画面，再组织结构。长视频可以分段理解，但最终笔记必须基于合并后的全局时间轴；先检查分片覆盖、重复和时间单调性，再写作。字幕或截图不能支持的结论应标记未展开或转写不确定，不自行补成原话。

推荐内容：核心内容、知识小节、知识地图、概念卡片、步骤或代码、自测与答案、回看索引和未确认内容。短视频可合并，结构与实际内容相称。知识地图用层级文本或列表。

以上游课堂模板为内容基础，采用 VidLens 的图文对应原则：截图支撑具体解释，标注实际时间；清晰但无关的画面不作为证据。QC 后仍应视觉复核。时间来自字幕、转写分片合并结果或抽帧清单。抖音显示时间并链接原片，不宣称精确跳转。

## 时间点、证据和不确定内容

- 重要观点、数字、步骤、代码和截图都应尽量附真实时间点；时间点必须来自 manifest、转写文本或图片清单，不能凭章节位置估计。
- 视频原话、模型根据视频做的转述、Agent 的补充解释要分开写。补充知识不能伪装成视频作者的结论。
- 图片必须支撑它所在段落的具体说明；只因为画面清晰、构图好看或出现在候选清单中，不足以作为插图证据。
- ASR 听不清、代词指向不明、术语无法确认或画面无法核验时，写“需要核对”或“未展开”，不要自行补全数字、因果和立场。
- 英文原话翻译成中文时标注“译文”，并保留来源和时间点；不要把意译写成未经标记的直接引语。
- 如果多个分片在边界处重复，合并后只保留一次；如果存在时间缺口，先在笔记的未确认内容中说明，不能用推测填补。

## 中间格式

note.json 由 Agent 编写，脚本仅验证与发布，不调用额外模型 API。examples/note.json 是演示格式，不是实际视频解读。

顶层字段：schema_version=1；非空 title（最多 200 字符）；summary（最多 2000）；source_key（与素材 manifest.source.key 相同）；sections（1–100 节）。每节包含唯一 id、title、非空 blocks。

图文笔记至少包含一个经过视觉复核的 image 块。没有图片时必须填写顶层 text_only_reason（1–1000 字符），解释实际提取失败、没有相关画面或用户要求纯文字的原因；该说明会显示在飞书正文和 Markdown 中，validate-note 会返回警告。图片路径存在并不等于笔记已插图，必须写入 blocks。已有冻结草稿按原内容恢复，不为补图改动同代笔记；补图应生成新版本。

| type | 字段 | 写入效果 |
|---|---|---|
| text | text，可选 seconds | 段落 |
| bullet | text，可选 seconds | 列表项 |
| code | text，可选 language、seconds | 飞书纯文本代码块，language 用于 Markdown 导出 |
| image | path、caption、seconds | 回看链接、图片、说明 |

text 内容是纯文本，首版不解释正文的 Markdown 加粗、HTML 或表格。对比可用列表表达。来源和回看链接由发布器根据可信元数据生成。

图片相对 note.json 所在目录，必须位于该工作目录内；支持 png/jpg/jpeg/webp，最大 20 MiB。禁止本机绝对路径、上级目录和远程图片 URL。换设备需保留相同相对路径和图片内容。

prepare 默认生成 images/manifest.json 候选清单，frames 中的 file 相对该清单目录、t 是实际解码帧的秒数。无字幕时可按时间分布抽帧；这些帧只供复核，不代表已理解视频内容。选择与章节相关的画面，用 images/<file> 作为 note.json 中的 path，t 作为 seconds，并将 caption 改为具体说明；不要把候选图的通用提示当成最终图注。首次查重可用 --no-screenshots 跳过提取，确定需要新生成后再默认 prepare。

同代笔记首次发布后冻结，内容或图片变化会触发哈希不一致。恢复原文件继续，或显式开启新版本。

## 校验与 Markdown 导出

    python scripts/vfn.py validate-note <note.json>
    python scripts/vfn.py render-markdown <note.json> --manifest <manifest.json> --output <note.md>

validate-note 检查结构、图片和时间类型；发布时还检查来源、时间范围、远端块完整性。Agent 在发布前还应抽查转写合并结果的开头、中段、结尾，以及支撑结论的关键片段；忠实性、概念质量和题目是否适合由 Agent 判断。

Markdown 建议导出到 note.json 同目录，以保持相对图片链接。飞书使用结构化块写入。上游 v3 Markdown 校验器针对不同语法，首版不直接调用它校验 note.json。

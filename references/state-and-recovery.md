# 状态、去重与恢复

## 所有权与状态

状态和发布命令都需要 record_id 与当前 run_id。新领取后旧 run_id 不能推进任务。单表只运行一个执行者，普通表格更新不是原子锁。更新时间用于观察，不触发自动抢占。

待处理 → 处理中 → 已完成；异常记录失败或待人工处理。已完成默认跳过。

- claim --retry：明确重试失败/待人工处理的相同输入，保留草稿。
- claim --resume：确认原执行已结束后恢复，保留 generation 和工作文档。
- claim --regenerate：新 generation 与新文档，处理中保留旧成功文档和链接；新版全部成功且表格链接回读一致后，再删除旧主文档与备份。

处理中改变链接、笔记要求、模板版本或语言时，后续推进会停止。用 fail --manual 记录原因，明确要求处理新输入时再 claim --regenerate。不能把旧输入结果标为新输入完成。

## 去重

视频元数据产生平台 ID 与分 P，再通过 bind-source 绑定。输入指纹是规范视频标识、笔记要求、模板版本、语言的 SHA-256。相同视频不同分享链接可复用，不同分 P 或要求分别处理。

复用要求来源记录已完成、指纹一致、有发布元数据、归档目标完全一致且文档 API 可访问。知识库还须回读节点，确认其为指定父页面下的原始 docx 节点，且正文 ID 一致；节点被移动或指向其他正文时不复用。手工填入链接及缺少目标信息的历史结果不视为已验证。重新生成跳过去重。

## 发布恢复

用 show <record_id> 先读取记录和检查点，不需要改变状态。

长视频 ASR 使用本地 `chunk-manifest.json` 和逐片 `chunk-checkpoints/` 恢复。每次只处理预算内的新片段；检查点与当前音频身份、时长及分片窗口不符时会停止复用或重做不匹配片段。达到单次片数上限后会保留下载音频供下次调用复用，全部转写完成后才删除该临时音频。任务目录必须保留在 `output/<record_id>/v<version>/`；移动设备或清理该目录后，无法从飞书任务表恢复本地音频和 ASR 检查点。

`doctor` 在独立子进程实际导入媒体依赖，`media_runtime` 列出检查过的解释器与失败原因；`asr_ready` 同时要求媒体环境和上游转写脚本就绪。它只诊断，不安装、不下载模型；`optional_modules` 仅表示当前 CLI 环境能否找到模块，不等于媒体环境可运行。

转写、截图、抖音获取会自动复用当前 Python、已验证的独立媒体环境或项目 .venv；全部不可用时，查找本机 Python 3.10–3.12，在 cache/media-runtime 下创建新环境并安装固定媒体依赖。验证通过才原子切换 active.json，不覆盖调用方环境、不移动虚拟环境、不删除旧环境或任务文件。也可提前执行 `video bootstrap`。配置、禁用与边界见 [setup.md](setup.md#视频处理工具)。

恢复后保持原输出目录、语言和热词，继续使用 chunk-manifest 与已完成 checkpoint。pip 安装最多尝试两次，每次超时十分钟；失败退出并保留旧环境，不把模型下载、平台网络、音频识别或飞书异常当作依赖问题反复重建。独占 install.lock 防止同时安装；遗留锁须先确认对应安装进程结束，再人工删除锁并重试。不会按文件时间自动抢锁。

ASR 新检查点同时绑定 `asr-settings.json` 的语言、词表、请求模型与设备。续跑参数变化时停止，恢复原设置或开启新版本。旧版缺少这些身份信息的未完成检查点保留原目录另建版本，不与新词表混合。空白窗口可以继续处理，全文无有效文字时为 `quality_failed`，保留音频和诊断供核对；已开始的分片任务不能因环境缺失自动切换整段方案。完整字幕或转写在 `transcripts/` 留存原稿、校正版及哈希；不要手改留存文件。校正中断可用同一 corrections.json 重试，prepare 会继续选用已验证的校正版；详见 [transcripts.md](transcripts.md)。

笔记转换为确定的根级块序列，保存正文与图片哈希。追加使用由 generation 和块序号生成的稳定 client_token。恢复先读实际子块，比对已写前缀，再补齐。图片已有 token 不重复上传；图片块存在但没有 token 时继续。每个确认块写检查点，首版以恢复可靠性优先，串行发布。

both 模式给云盘生成备份与知识库主文档分别保存创建保护、正文 ID、已写进度与校验结果，追加 client_token 同时绑定正文 ID，避免副本之间混用。先写云盘备份，再写知识库主文档；恢复时已完成的目标只回读核验，不再追加或上传。只有两份均验证成功且输入未变才统一回填完成。某处失败保留另一处成果和上次成功链接，不删除或回滚；整体任务仍在处理中时，人工改动任一已写目标会停止恢复，避免将修改后的内容误判为原始生成结果。

整体任务完成后，日常整理和修改都在知识库主文档进行，已完成任务默认跳过；主文档的后续修改不更新云盘生成备份。备份保留最初生成的内容，不持续同步，也不自动备份后续手动修改。重新生成会创建新主文档和新备份；旧文档及旧链接保留到新版发布、图片校验和表格链接回读确认全部成功后，再清理旧主文档和备份，默认仅留最新版。

## 旧版清理与恢复

领取新版本时，将与当前表格链接一致的已成功发布元数据写入 version_cleanup 队列。只清理有明确检查点的旧版本，不从手工链接猜测文档 ID，不追溯扫描历史文档。尚未清完的队列会跨失败和新版本保留。进行中的草稿不属于成功旧版清理范围。

清理前重新校验新版正文、图片 token 和知识库节点，并逐张下载新版远端图片核对原图 SHA-256；图片取不到或内容不一致均不删除旧版。再回读表格，确认状态已完成、run_id、generation、输入和全部链接仍匹配。清理只操作旧文档正文 ID，拒绝当前文档；被其他任务链接或检查点引用的文档暂不删除。旧知识库页面须仍在原位置、关联正文一致且明确无子页面，否则保留并提示。

删除使用飞书文件删除接口，进入回收站，不清空回收站。需具备删除 API 权限及资源管理权限；知识库文档删除能否生效以实际接口结果和回读为准，正文及知识库节点都确认不可读且返回明确的不存在/已删除错误后才记为删除成功。权限失败或删除响应丢失会保留进度与错误，新版继续保持已完成，“当前阶段”显示旧版清理待重试；不能因此 fail 或再开一个生成版本。恢复时先读旧文档是否已删除，再决定是否发送删除请求；权限不足不视为已删除。

修复问题后使用同一运行标识与未改动的笔记、图片，仅重试清理：

    python scripts/vfn.py cleanup-versions <record_id> --run-id <run_id> --note <原note.json>

该命令不创建文档，不切换表格链接。返回 pending 为 0 才代表清理完成；若表格输入、链接或所有权已变则停止，不能用旧检查点覆盖新状态。

| 情况 | 操作 |
|---|---|
| 素材阶段中断 | 确认原执行结束，claim --resume；素材可用则复用，否则重新获取 |
| 追加成功但响应丢失 | 再次 publish 先回读核对，避免重复 |
| 文档完成、表格未回填 | 同 note.json 再 publish，校验后补写状态 |
| 草稿被手动编辑或多出块 | 停止追加，人工核对，不覆盖人工内容 |
| 内容或图片变了 | 同代拒绝发布，恢复原文件或开新版本 |
| 文档创建但 ID 未保存 | 保存报错中的 ID，或按检查点标题查找空草稿后 attach-document |
| 创建结果未知 | 保留 creating 检查点，不重复创建 |
| 知识库节点创建成功但响应或检查点丢失 | 按保存标题在原父页面查找，解析正文 ID 后 attach-document，不重复创建 |
| 配置中的归档目录改变 | 停止续写；恢复原配置，或明确重新生成新版本 |
| 草稿知识库节点被移动或关联了其他正文 | 停止续写，人工核对；不标记完成 |
| 只完成云盘生成备份 | 保留备份检查点，明确重试后校验备份，只继续知识库主文档 |
| 双归档全部写完但表格回填失败 | 同笔记重试，回读两份后统一回填链接，不创建新文档 |
| 新版完成但旧版清理失败 | 保留新版已完成状态，cleanup-versions 只重试清理 |

恢复创建结果未知的空草稿：

    python scripts/vfn.py attach-document <record_id> --run-id <run_id> --document-id <核实后的文档ID>
    python scripts/vfn.py publish <record_id> --run-id <run_id> --note <原note.json>

attach-document 确认标题完全匹配已保存创建尝试，且文档为空。若确实未创建文档，人工核实后再开启新版本，不自动清除创建保护。

wiki 模式仍向 attach-document 传正文 document_id（obj_token），不能传 node_token。可先用 wiki-node <核实后的节点token> 查得 obj_token。恢复时额外核对知识空间、父节点、origin/docx 类型和正文 ID，保存节点检查点后继续；无需人工移动页面。

both 模式恢复未知创建结果时必须明确目标，例如：

    python scripts/vfn.py attach-document <record_id> --run-id <run_id> --target wiki --document-id <知识库正文ID>

云盘创建未知时使用 --target folder。每次只关联该目标的空草稿，不改动另一处检查点。

publish 检查点保存 destination（归档类型和目录）、wiki_node（知识库节点与正文 ID）；published 还保存 wiki_node_token 与知识库 URL。创建前保存目标和创建意图，创建后立即保存节点与正文 ID。创建响应缺字段或无法验证时保留创建保护，不盲目重试。

可安全重放的读取与确定值更新最多重试 2 次；创建等不确定写入不自动重放。schema --apply 失败后应先重新读字段。

## 完成判定

读回预期块数、核对正文和链接、确认图片 token、当前调用身份可读文档；wiki 模式还须再次回读并校验节点归属与正文 ID，再回填 /wiki/<node_token> 链接。both 模式在最后一处完成后再次核验两处，将知识库主文档链接回填“笔记文档”、云盘生成备份链接回填“备份文档”；核对任务输入和执行标识后回填摘要、时间、已完成状态并清除重新生成标记。其他读者权限由知识库或文件夹配置决定，首次部署请用户分别打开验证，不自动公开分享。
